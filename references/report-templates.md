# 输出模板

写作要求：
- 先给结论，再给依据。
- 数字都来自脚本输出。
- 每条“研究表明”后面带 [证据编号]。
- 经验做法要标明“经验做法”。
- 用户看不懂的术语，第一次出现时用括号解释，例如“LT1（第一乳酸阈，轻松跑心率的上限）”。
- 不写空话，例如“坚持就是胜利”。

---

## 5. 周复盘（`weekly.py` 的输出整理成）

先问一次疼痛（0–10，部位），然后运行 `weekly.py --pain N [--where 部位] [--ifthen "预案"]`。复盘只做三件事：对账、发现偏离、写预案 [BCT-1][BCT-3]，不做激励 [BCT-6]。

```
# 周复盘（MM-DD 至 MM-DD）

计划 X km、N 节课；实际 Y km（Z%），完成 n 节；关键课 a/b。
- 没做的课：<课名>——没做（不补，也不挪到下周）
- 单次跑量（P1）：没有超过 / <哪一次超过多少> [LOAD-3]
- 疼痛：<分数和部位；≥4 或影响跑姿 → 停跑 48 小时、看医生 [D3]；1–3 → 盯三件事（跑时不超过轻中度、第二天早上恢复、一周比一周轻），这是经验做法，思路来自跟腱病研究 [INJ-5]>
- 恢复（只记录）：HRV …，静息心率 …，睡眠 …
- 下周最重要的一节：<日期 课名>；<超过 P1 上限的课和建议的长度>
- 预案：上次的“如果……就……”用上了吗？下周的是：…
后面的骨架不变；没做的课不补。
```

措辞规矩：
- 不写“落下了”“要补回来”“偷懒”这类带内疚的话；没做就是“没做（不补）”。
- 完成度长期偏低时，说“到下一个检查点按实际情况重估目标”[ILL-3]，不说“加把劲”。
- 用户说手表分数让他焦虑时，用 `weekly.py --light`（只给 5 行），平时少看每日分数 [UNC-4]。
- 已经 8 天以上没跑时，先走“中断后复训”（`resume.py`）。

可以定时：在支持定时任务的智能体里，每周一早上自动运行 `garmin_pull.py --days 10` 和 `weekly.py`，再把结果发给用户、请他补上疼痛分数。定时运行用的是本机保存的密钥；密钥过期后要用户本人重新设置。

## 6. 单次课复盘（最多 12 行）

```
<日期> <课名>：完成 / 部分完成 / 改了
- 配速：第 1–N 组 …（目标 …）→ 在区间 / 快 X 秒 / 慢 X 秒
- 心率：…（目标 …）；<心率数据是否可疑>
- 组间恢复：心率降 …（和你以前同类课比 …）
- 稳定段：同配速心率比近 8 周 ±X bpm（气温 …）   ← 轻松跑/长距离才有
- 你的感受：用力 X/10 …（没填就问）
结论：这次课 <达到目的 / 偏轻 / 偏重>，原因 … [证据编号]
下次同类课：<一条具体的执行建议>；课表不变（只在检查点调整）。
```

比赛或长距离（脚本多给一节“比赛配速分析 / 长距离配速与耐久性”）时，在上面的模板后加：
```
- 分段：前后半程 X vs Y（后半程慢/快 Z%）；配速波动 …；人群参考 … [PACING-2]
- 撞墙：最后约 12 km 比第 2–16 km 慢 …%（>25% 算撞墙）[PACING-1]；前段速度占临界速度 …%（>94% 风险更高）[PRED-5]
- 耐久性：心率/速度比最后 5 km 为 …，从第 … km 开始脱钩 [HRP-3]
- 天气：… °C，WBGT 粗估 … [WBGT-1]
下一场比赛：<配速策略、补给、天气方面各一条可执行的建议>
```

## 8. 生成信息（每份报告和课表说明的最后一行）

发给用户之前，先把要发的文字存成文件，运行 `check_refs.py report 文件 --stamp "模型名"`：
- 有 ERROR（编号不存在、正文手写了 PMID/DOI）就先改。
- 有 WARN（“研究表明”后面没有编号，或依据全是 C 级/未核实）就改成“经验做法/不明确”。
- 通过后脚本在文末加一行：技能版本、模型、日期。不同模型跑同一个技能，结果会有差别，这一行方便以后对照 [AI-5][AI-7]。
